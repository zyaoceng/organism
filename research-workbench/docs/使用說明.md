# 研究工作台（Research Workbench）使用說明

## 要搞懂什麼

這個網站把一次研究記成一條鏈：證據 → 假設 → 財務數字 → EPS → 目標價，之後再接交易和檢討。
每次改變看法都存成一筆「研究更新」，幾個月後可以查回當時相信什麼、為什麼、哪份資料讓你改變想法。

## 怎麼把網站跑起來？

**在自己的電腦上執行三行指令，然後用瀏覽器打開 http://localhost:5173 。**

- 電腦需要先裝 Node.js 20.10 以上的版本。
- 在 `organism` 資料夾裡依序執行：

```bash
cd research-workbench
npm install
npm run dev
```

- `npm install` 只有第一次要跑，之後每次只要 `npm run dev`。
- 想先看一家已經填好數字的範例公司，在 `npm run dev` 之前多跑一次 `npm run seed:demo`。範例公司是虛構的，股價也是系統產生的假資料。
- 所有資料存在 `research-workbench/data/` 資料夾。備份就是複製這個資料夾。
- 網站沒有登入功能，只在你自己的電腦上開放，不要架到公開網路上。

## 第一次研究一家公司要怎麼做？

**照「建立公司 → 填歷史數字 → 填預估 → 附上證據 → 提交」五步走。**

1. 首頁按「+ New company」。填公司名、股票代號（例如 2301）、交易所（TWSE）。代號欄會自動變成 `2301.TW`。股價來源選 `Yahoo`；連不上時先選 `Demo` 或用 CSV 匯入。
2. 網站用標準研究模板建立一棵樹：EPS 底下有營收、毛利率、費用、業外、稅、淨利、稀釋股數；P/E 底下有 EPS 成長、ROIC、再投資報酬率；最下面是目標價。期間預設 2024A、2025A、2026E、2027E、2028E，金額單位是新台幣億元。
3. 把 Business A、B、C 改成你自己的業務切法。點一列，按 `F2` 改名，按 `A` 新增子項目。管理層的部門分法不好用時，照你自己的分法切。
4. 在實際年度（A）的格子填財報數字，在預估年度（E）填成長率、毛利率等假設。點格子直接打數字，按 Enter 換下一列。百分比格打 `40` 就是 40%。
5. 選一個重要假設，在右邊面板加上證據：貼網址按 Enter、把 PDF 拖進去、`Ctrl+V` 貼截圖，或寫一則筆記。
6. 按畫面底部的「Review & commit」，寫標題、知識日期（你知道這些資訊的日期）、理由，按「Commit Research Update」。

## 樹狀圖上的顏色和記號是什麼意思？

**藍字是你手打的數字，黑字是公式算出來的，黃底是還沒提交的改動。**

- 灰底欄位是實際年度，白底是預估年度。
- 格子左邊的小圓點代表這格有空頭或多頭情境的覆寫值。
- 格子右上角的橘色三角代表你在公式格手打了數字，蓋掉公式結果。這通常是錯誤來源，右邊的「Model checks」會列出來。
- 深黃底是你直接改的格子，淺黃底是被連動改到的格子。
- 列名後面的 `ƒ` 代表有公式，`📎2` 代表連了兩份證據，`!` 代表有錯誤。
- 點一列後，這一列公式用到的列會出現藍色「in」，用到這一列的列會出現橘色「uses」。公式跨到其他分支時，靠這個看出關聯。

## 公式要怎麼寫？

**在右邊面板的 Formula 欄用中括號寫名稱，按 `Ctrl+Enter` 套用。**

- 例子：`[TAM] * [Market Share] * [ASP]`。
- 去年乘成長率：`PREV([營收]) * (1 + [成長率])`。`PREV` 讀前一期，不算循環參照。
- 產能上限：`MIN([市場需求], [產能])`。
- 加總底下所有子業務：`SUM(CHILDREN())`。之後新增的業務會自動算進去。
- 指定某一年：`[EPS]@FY2028`。目標價公式預設是 `[EPS]@FY2028 * [Target P/E]`。
- 打中括號時會跳出名稱清單可以點選。
- 公式形成循環時會被擋下，並顯示循環路徑，例如「EPS → 淨利 → 稅 → EPS」。
- 輸入值空白時，下游格子會顯示「—」，滑鼠移上去會寫缺哪一格。系統不會把空白當成 0。

## 空頭、基準、多頭三種情境怎麼設？

**基準情境放共用數字，空頭和多頭只記跟基準不同的格子。**

- 畫面左上角切換 Bear / Base / Bull，或在樹上按數字鍵 1、2、3。
- 在空頭情境下改格子，只會記成空頭的覆寫，基準數字不變。
- 右邊面板的 Values 表同時列出三種情境，灰色斜體代表沿用基準。
- 實際年度三種情境共用，改不了覆寫。

## 收到新資訊時要怎麼更新？

**先附證據，再改所有相關假設，最後一次提交成一筆研究更新。**

- 同一份新資訊可以同時改多個假設，例如市占率、產能、毛利率。
- 改完先打開底部面板，會看到三樣東西：改了哪些格子、EPS 和目標價在三種情境下怎麼變、影響一路傳到哪些科目。
- 提交後，系統會算出每個假設單獨造成多少 EPS 和目標價變動。
- 看完新資訊決定不改任何數字時，照樣可以提交，這筆會記成「checkpoint」，代表你看過並維持原判斷。
- 知識日期不能比上一筆早，也不能引用在知識日期之後才發表的資料。這是為了避免事後諸葛。
- 改錯了可以按 `Ctrl+Z` 復原；還沒提交的草稿可以整份丟棄。

## 目標本益比要怎麼決定？

**在 Valuation 頁自己輸入三種情境的本益比，系統只負責整理判斷用的資料。**

- 這一頁列出 EPS 成長、ROIC、再投資報酬率、毛利率，以及目前股價換算的本益比。
- 歷史本益比區間和同業表要自己填，每一格可以寫來源和日期。
- 每種情境的本益比旁邊要寫理由，這些理由會跟著研究更新一起存檔。
- 可以填三種情境的機率，系統會算出機率加權目標價。

## 幾個月後怎麼回頭檢討？

**打開 History 頁，所有研究更新都在時間軸上，每一筆都能完整還原。**

- 點任一筆更新，會看到當時的理由、引用的證據、改了什麼、對 EPS 和目標價的影響，以及當時的股價。
- 按「View snapshot」可以用唯讀模式看當時的整棵樹、當時連結的證據、當時的論點。
- 按「Restore into draft」會把舊版本放回草稿，提交後成為新的一筆，舊紀錄不會被改寫。
- 「Estimate evolution」分頁畫出同一個數字（例如 2028 年 EPS）在每次更新時的估計值。那一年財報公布、期間改成實際（A）後，會多一條實際值的線，直接看出估計誤差。
- 右邊面板最下面的「Change history」會列出這一格每次被改的日期、數字和理由。
- 「Reviews」分頁可以寫檢討，勾選錯誤出在證據品質、證據解讀、假設幅度、模型公式、時機、本益比、交易執行或風險控管。分類由你判斷，系統不會自動歸因。

## 交易紀錄要怎麼用？

**在 Trades 頁記錄進場，系統自動帶入當天的 ATR、2 倍 ATR 停損和當時的目標價。**

- 目標價取自進場日當天已經提交的研究更新，進場日之後才做的研究不會被拿來用。
- 出場後填出場日期、價格和理由。
- 表格會算報酬、R 倍數、持有期間最大浮盈和最大浮虧，也會算「照 2 倍 ATR 移動停損會在哪天出場」。
- 拿這兩個數字比對，可以分開檢討「研究判斷錯」和「交易執行差」。
- Market 頁的 K 線圖會標出進出場點、停損線和三種情境的目標價線。

## 其他常用功能在哪裡？

**`Ctrl+K` 搜尋全部內容；Overview 頁可以匯出和存成模板。**

- 搜尋範圍包括節點名稱、筆記、證據、催化劑、論點和研究更新的理由。
- Catalysts 頁記錄法說會、客戶認證、新廠量產等事件。事件發生前先寫預期結果，事後補上實際結果；舊版本會自動保留。
- 在任何一個節點的右邊面板可以寫「論點」和「推翻條件」，例如「FY27 開始導入 800V；若 FY27 Q2 前沒有雲端大廠認證就推翻」。
- Overview 頁的「Export JSON」下載整家公司的完整紀錄；「Save as template」把這家公司的樹狀結構存成模板，下一家公司可以直接套用。

## 常用快捷鍵有哪些？

**在樹狀圖上點一下之後，以下按鍵才有作用。**

| 按鍵 | 作用 |
|---|---|
| `A` | 新增子項目 |
| `S` | 新增同層項目 |
| `F2` | 改名 |
| `Tab` / `Shift+Tab` | 往內縮／往外移一層 |
| `Alt+↑` / `Alt+↓` | 上移／下移 |
| `Ctrl+D` | 複製整個分支（公式會自動改成指向複本） |
| `Delete` | 刪除（可用 `Ctrl+Z` 復原） |
| `1` `2` `3` | 切換空頭／基準／多頭 |
| `Ctrl+Z` | 復原 |
| `Ctrl+K` | 搜尋 |
| `Ctrl+V` | 把截圖貼成證據，連到目前選取的節點 |

## 目前有哪些限制？

**Yahoo 股價來源還沒實測過，連不上時請改用 CSV 匯入。**

- Yahoo 用的是非官方介面，開發環境的網路擋掉了它，所以沒有實際驗證過。
- CSV 匯入支援 Yahoo 的欄位格式，也支援證交所的中文欄位（日期、開盤價、最高價、最低價、收盤價、成交股數）。
- 一個模型只能用一種期間頻率，年度或季度擇一。
- 可以匯出 JSON，還不能匯入。
- 網站介面是英文，節點名稱、筆記、證據都可以寫中文。
